Executive Brief

RAVEN is in good structural health. Its dependencies are clean — npm audit reports zero open advisories at the reviewed commit, and Dependabot closed four advisory classes within nine days during September. Its security design is better than typical for an internal tool: it never holds more authority than the person running it, its audit log is cryptographically tamper-evident, and personal information is scrubbed before any content reaches an AI model. The material risk is concentrated in one place. Two confirmed command-injection defects allow an attacker who can influence text in a ticket or an application log to run commands on BC Government application servers under a privileged service account. These are not two separate bugs but one duplicated one: two packages independently implement the same shell-safety check, and the two copies have already drifted apart so that each blocks characters the other misses. Reachability analysis shows the affected code is called from the autonomous pipeline, which runs on a schedule with no person watching, widening the exposure beyond what a first-pass review identified. Separately, the FOIPPA privacy scrubber does not redact a social insurance number or phone number written without separators, nor a bare IDIR — a compliance gap in the exact control the privacy posture depends on. None of this is an emergency: every path requires an attacker to already be writing content the system reads. The recommended first step is roughly a day of focused work that closes the whole class rather than the individual instances.

High-Risk Security Issues

Critical and high-severity findings requiring immediate attention. Confirmed findings have full code evidence; Probable findings await complete verification.

FindingSeverityClass.Business RiskAction
RSEC-001 — Command injection in Server MCP log search Critical Confirmed An attacker who can influence text in a ticket or an application log can run arbitrary commands on BC Government application servers under a privileged service account. Reachable from seven call sites across four packages, including the autonomous pipeline that runs unattended on a schedule. Escape the search pattern per-argument instead of extending the character denylist; ship together with RSEC-002 and RSEC-003.
RSEC-002 — Command injection via newline bypass of the IMIS allowlist Critical Confirmed The same class of defect in a second package. A newline in a command argument passes the safety check because the check treats a newline as ordinary whitespace, then acts as a statement separator on the remote shell. Add newline, carriage return and quote characters to the check, and consolidate both packages onto one shared, tested command builder so the copies cannot drift again.
RSEC-003 — Path validation accepts newline and quote characters High Confirmed This is the delivery route for RSEC-002. A file path supplied through an AI tool call reaches an unquoted shell command, so a path containing a newline executes. Extend the character check and quote the path where it is interpolated. Fix alongside RSEC-002.
RSEC-004 — Privacy scrubber misses unseparated SIN, phone and bare IDIR High Confirmed FOIPPA compliance gap in the exact control the privacy posture depends on. A social insurance number written as nine consecutive digits — the common machine-readable form — passes through unredacted to an AI model and into audit records, as do unformatted phone numbers and bare IDIRs. Make separators optional, add a bare nine-digit branch with a checksum test to limit false positives, add a standalone IDIR pattern, and lower the credential length threshold. Over-redaction is the safe direction here.
RSEC-005 — Local dashboard has no authentication or CSRF protection Medium Confirmed Any website the operator visits can read the internal server inventory — hostnames, SSH usernames, sudo accounts — or overwrite the server configuration file, using the operator's own privileges. Add Host and Origin validation plus a custom-header requirement on state-changing requests, and sanitize values written to the configuration file.
RSEC-006 — SSH host key verification disabled in both SSH clients Medium Confirmed Both SSH clients accept any host key presented, then send the SSH credential and the sudo password. An attacker positioned on the network path could capture both. Documented in code as a deliberate decision treating the VPN as the trust boundary, but the exception is implicit and duplicated. Verify against known_hosts and gate the bypass behind one explicit opt-in flag covering both sites. Record the decision as an architecture decision record.
RSEC-007 — TLS certificate validation disabled for alert email Medium Confirmed Every alert email is sent with certificate checking switched off. Where SMTP credentials are configured, those credentials and the alert contents — internal hostnames and stack traces — can be intercepted. Remove the default and require an explicit opt-in environment variable for the insecure mode.
RSEC-008 — Push credentials transiently written to git config Low Probable An abnormal termination during a pipeline push can leave the operator's password in plain text in a local git configuration file. Port the credential-header pattern already implemented in the Bitbucket package. This is a copy of proven in-repo code, not a new design.
RSEC-009 — Unescaped markdown in the Confluence converter fallback Low Probable If a markdown render throws on untrusted content, the error path returns the raw input unescaped into Confluence page storage. HTML-escape the fallback return value.
RSEC-010 — Webhook validation does not resolve DNS Low Probable Alert webhook validation blocks private IP addresses written literally but never resolves hostnames, so a domain pointing at an internal or cloud metadata address is accepted. Resolve the hostname at dispatch time and re-check the resolved addresses.
RSEC-011 — Missing HTTP security headers on the dashboard Informational Confirmed No content security policy or framing protection, so the local dashboard can be embedded by another page for clickjacking. Mount the helmet middleware when the application is created.
RSEC-012 — No code coverage provider is installed Informational Confirmed Coverage reads zero and fails the quality gate. The cause is not scan configuration — no coverage tooling exists in the project at all, so no amount of re-scanning will produce a number. Install a coverage provider, configure LCOV output, and establish a real baseline before setting any coverage threshold.
RSEC-013 — Continuous integration has no security scanning gate Informational Confirmed The build runs a real compile and the full test suite but no dependency audit or static security analysis, so an advisory published after a merge is never caught by a gate on the change itself. Add a dependency audit step to the workflow and enable code scanning in repository settings. This directly supports the goal of automating dependency maintenance.

Strategic Remediation Roadmap

P1
Immediate — Current Sprint
Close the command-injection class in one change — RSEC-001, RSEC-002 and RSEC-003 are one defect duplicated across two packages, so fixing a single package closes the ticket without closing the hole. Extract a shared, tested command builder using per-argument escaping and add the reproduced payloads as regression tests. In parallel, fix the privacy scrubber patterns so unseparated identifiers are redacted; this is cheap and it is the control FOIPPA compliance rests on.

Short Term — 1-2 Sprints
Add Host and Origin validation to the local dashboard and sanitize configuration writes. Enable SSH host key verification at both sites behind one explicit opt-in flag, and record the trust-boundary decision as an architecture decision record.

Gate the SMTP TLS bypass behind an opt-in variable. Port the existing in-repo credential-header pattern into the pipeline push path.
